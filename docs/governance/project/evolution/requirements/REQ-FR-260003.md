## Statement

The system shall present, on opening the app at the gym, exactly the exercises planned for the day
being trained — in planned order, each with its planned set count, its target reps and whatever is
already logged against it today — without the user searching for them or choosing a date, and with
the first set enterable one step from that screen.

## Rationale

This is the outcome the owner named first: "when the user goes to the gym, he/she wants to know
which exercises to do on that day, how many sequences and how many reps". Two verified backend
facts decide how it can be built. Atoms carry no timestamps and `retrieve` takes no temporal
argument — `AtomOutput` ([`schema.graphql:249-263`](../../../../backend/schema.graphql)) has
neither `createdAt` nor `updatedAt` while `WorkspaceOutput` and both category outputs do — so the
training date is data Liftrack writes and reads back, and stays so even if atoms gain timestamps:
record time is not training time. And `retrieve` silently returns at most 25 atoms, with no way to
raise that bound or to detect it bit (`_DEFAULT_RETRIEVE_LIMIT = 25`,
`inter_fundamentals.py:1406-1407`, applied at `:1419`; `resolvers.py:86-91` forwards no limit), so
this screen must be built from reads bounded by one day's data, not by accumulated history, or it
degrades silently mid-workout with no sign an exercise is missing. REQ-CR-260003 carries the
general no-silent-truncation rule; this record fixes the read shape that stays clear of it.

## Acceptance Criteria (behavioral)

- End-to-end: a cold open with no in-tab state lists the selected planned day's exercises and no
  others, in authored order, with planned sets and target reps, first set enterable in one action.
- End-to-end: with sets already logged today, the same cold open shows per exercise which sets are
  recorded, with their actual reps and weight, and which remain to be done.
- End-to-end: the workout shown is the one for the device's current local calendar date; moving the
  device date to the next training day presents that day's exercises with an empty log.
- End-to-end: opening on a day with no planned day selected presents an explicit choice of planned
  day — never a blank screen, an error, or an arbitrary default.
- End-to-end: the reads that build this screen return the same number of rows and the screen renders
  within REQ-QR-260002's budget for an account holding 12+ months of logged sessions as for one on
  its first day, and no such read returns a result at the backend's page bound.
