## Statement

The system shall let a user maintain a personal exercise catalogue — creating and editing entries by
name — and shall let the user author, away from the gym and before any session, a plan made of named
planned days, each listing exercises drawn from that catalogue to perform in an explicit user-chosen
order with a planned number of sets and a target rep count or rep range per exercise, and shall let a
planned day be revised later without altering any session already logged against it.

## Rationale

The owner's statement is that the user "wants to know which exercises to do on that day, how many
sequences and how many reps", and that "all of this was planned upfront". "Which exercises" only has
an answer if the user can put exercises into the system in the first place — a plan cannot list what
the catalogue does not contain, so authoring the catalogue is not a separate feature bolted onto
planning, it is planning's precondition. Planning is a separate activity from logging, and the plan
is the sole input to REQ-FR-260003. Three further properties make plan authoring authoring, not
note-taking: order is part of the plan (which lift comes first is a training decision); the planned
sets and reps are what the user checks themselves against mid-session; and a plan is edited across a
block, so an edit must not rewrite history. That last is not free here: an update replaces every
field it carries and leaves the rest unchanged, with no merge
([`backend-user-guide.md:931-932`](../../../../backend/backend-user-guide.md)), so "editing the
plan does not touch the log" is a claim to be tested, not assumed.

## Acceptance Criteria (behavioral)

- End-to-end: creating a new exercise by name adds it to the catalogue and makes it selectable when
  authoring a planned day; editing an exercise's name updates every planned day that references it on
  next read, without duplicating the entry.
- End-to-end: authoring a planned day with three catalogue exercises in a stated order, each with a
  planned set count and target reps, then signing in from a cold start on the same device, presents
  the same planned day with the same exercises in the same order and the same numbers.
- End-to-end: reordering exercises within a planned day persists that order, and today's workout
  (REQ-FR-260003) renders the authored order — not creation order, not alphabetical order.
- End-to-end: a target may be authored as a single rep count or as a low–high range; both round-trip
  unchanged and both render at the gym.
- End-to-end: a plan may hold more than one planned day, and the user selects which planned day a
  given gym visit follows; no planned day is auto-assigned to a date.
- End-to-end: editing a planned day's exercises, order or numbers after a session has been logged
  against it leaves that session's recorded sets, reps and weights unchanged on read-back.
- Contract check: an edit to a planned day reads back with its label set and its untouched fields
  intact — an update that changes only the exercise list never drops a label or clears another field.
