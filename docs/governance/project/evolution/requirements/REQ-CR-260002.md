# Requirement: REQ-CR-260002 `Browser-only secret handling over an HTTPS backend origin`

Single requirement record. The ID encodes the class: `REQ-FR-…` (functional behavior),
`REQ-QR-…` (quality attribute), `REQ-OR-…` (operational), `REQ-CR-…` (constraint/compliance).
Status values: see `docs/governance/generic/process/artifact-model.md`.

- Requirement ID: `REQ-CR-260002`
- Title: `Browser-only secret handling over an HTTPS backend origin`
- Class: `CR`
- Status: `Proposed`
- Owner: `Repository owner`

## Statement

The system shall carry no secret in its repository or published artifact, shall reach the
Crystord Engine only over an `https://` origin, and shall treat the user's runtime session token
as its sole bearer material, handled as [ADR-260005](../adr/ADR-260005.md) decides.

## Rationale

A GitHub Pages artifact is world-readable even when the repository is private, and re-deploying
does not un-publish what was shipped, so anything secret placed in a build is disclosed
permanently. With no server of its own, Liftrack also cannot hold a secret anywhere else. The
transport half is equally absolute: a page served over HTTPS that calls an `http://` endpoint is
blocked as mixed content, with no user override, surfacing as a generic network failure that
names nothing about the scheme — so it must be caught before publishing, not after.

## Acceptance Criteria (behavioral)

- No credential, API key, client secret, password or session token exists in the repository or in
  any published file, verified by a secret scan over the build output that fails the deploy.
- The configured GraphQL endpoint begins with `https://`, asserted positively by the deploy
  pipeline. A denylist of known-local hosts is explicitly insufficient: an `http://` LAN
  hostname passes such a check and produces an artifact that is mixed-content-blocked on
  arrival, with no diagnostic naming the cause.
- The session token is obtained only at runtime from `signin`, `signinGoogle` or
  `completeSignup`; it never appears in a URL, query string, routing fragment, log line or the
  diagnostics surface of [REQ-OR-260002](REQ-OR-260002.md), and it is cleared on logout and on
  any re-authentication signal.
- If Google sign-in ships, the build carries a Google **client ID** only — public by design — and
  no client secret anywhere, which the in-page ID-token flow required by
  `signinGoogle(idToken: String!)` (`schema.graphql:11`) makes possible.
- The page's `<meta>` Content-Security-Policy restricts `connect-src` to the backend origin (plus
  the Google identity origin when Google sign-in ships) and forbids `unsafe-eval` and inline
  handlers. Controls that require response headers — `frame-ancestors`, HSTS, COOP/COEP — are
  recorded as unavailable on GitHub Pages rather than claimed as satisfied.
